## What this round built

### 1. Hosted brand-preview API (backlog #1) - live

`worker/` is a Cloudflare Worker: `POST /api/preview {url}` opens the reader's site in
Browser Rendering's real headless Chrome and returns `brand.json` plus a live preview
screenshot, usually in 4-8s. `extract.ts` is a scoped port of `tools/brand-from-url.mjs`:
`extractInPage` (the in-browser DOM walk) ports verbatim since it is a pure browser-context
function with zero Node dependencies; the colour-role decision engine (`decideBrand`) ports
the same maths against one hero-viewport pixel histogram instead of the local tool's
hero+full-page pair, to fit well inside the ~60s budget. Font and logo *files* are out of
scope for this fast path (names/a source URL only) - the local tool stays canonical for an
actual film. `public/index.html` is the landing page (URL box, live render, CTAs), served
directly by the Worker's static-assets binding.

Guards against SSRF on the user-supplied URL: rejects loopback, link-local (including the
169.254.169.254 cloud metadata address), RFC1918 private ranges and non-http(s) schemes
before a browser session is ever acquired. Verified against 127.0.0.1, 169.254.169.254 and
malformed input (all correctly rejected with 422/400), and against a real public site
(`example.com`, real extraction, real screenshot, 200 OK).

**Deployed and live:** <https://launch-video-kit-preview.subasiarhan3.workers.dev/> - this
account already has Browser Rendering enabled (confirmed by a real browser session running
during `wrangler dev --remote` testing), so this shipped as a real deploy, not just code
ready for one. Zero cost: Workers free tier + Browser Rendering's free allowance.
